具身智能体（Embodied Agents）与控制运行时深度调研：从综述索引到外挂架构与开源生态

截至 2026 年 11 月，具身智能（Embodied AI）领域的技术演进正沿着两条互补且并行的主线推进：一条是以 Figure AI Helix 02 与 Google DeepMind Gemini Robotics 2 为代表的“端到端全身神经网络栈”1，另一条则是以 GitHub 开源项目与 arXiv 论文密集涌现的“具身智能体外挂运行时（Embodied Agent Harness）”4。从 benchflow-ai/awesome-embodied-agents、wadeKeith/Awesome-Embodied-AI 等社区精选索引4，以及 2026 年 11 月发布的综述《Beyond the Model: A Survey of Harness Software for Embodied Agents》出发6，多篇近期研究与综述指出：单纯扩大视觉-语言-动作模型（VLA）的参数规模或拉长观测上下文窗口，仍难以根本消除长程物理操作中的历史记忆遗忘、执行前可行性校验缺失与异常级联崩溃问题9。

2026 年以来，围绕“外挂运行时编排、显式记忆、状态校验与自我演化”的技术路线，研究界与开源社区陆续推出了 Harness VLA（开源仓库 RLinf/RPent）、Zetta、HELM / HeLM、HarnessPAI、SHAPER、SERA 与 ROSClaw 等代表性工作5。在抗扰动桌面操作与家居操作基准（如 LIBERO-Pro 与 RoboCasa365）上，外挂架构在不微调底层 VLA 权重的前提下取得了 25.4 至 61.6 个百分点的任务成功率提升5；而在系统工程侧，基于 MCP（Model Context Protocol）与 ROS 2 执行层契约的中间件已将 Claude Code、Codex、OpenClaw 等编码与推理智能体直接接入仿真器及真实机器人硬件17。

在解读本报告梳理的定量数据时，需要明确三项方法论边界：其一，2026 年核心工作中有相当比例尚处于 arXiv 或 Preprints.org 预印本、匿名评审（如 EVA）及厂商或作者项目页发布阶段（如 Figure AI、Google DeepMind、HarnessPAI），尚未全部经过独立第三方同行评议复现1；其二，各方案采用的冻结基座策略、规划器步数/时间预算（如 RPent 单回合超时上限设为 7,200 秒）及评测任务子集（如 Goal2Skill 的定量主表聚焦 RMBench 中选定的 5 项任务）差异显著，横向指标不可脱离实验设置直接混比22；其三，部分开源索引（如 benchflow-ai/awesome-embodied-agents 的 README 正文）在调研抓取时存在访问受限，仅可核验其公开元数据与检索摘要4。

文献检索起点：核心综述（Surveys）与 GitHub Awesome 导航

开展具身智能体与控制运行时的系统性追踪，最高效的切入点是梳理软件边界的元综述（Surveys）与持续更新的 GitHub Awesome 资源索引4。

在综述维度，2026 年 10 月至 11 月的一批文献首次将“模型之外的运行时软件（Harness Software）”从传统模型中心视角中剥离出来，作为独立的研究对象进行分类建模6。2026 年 11 月发表于 Preprints.org 的《Beyond the Model: A Survey of Harness Software for Embodied Agents》（DOI: 10.20944/preprints202611.1642.v1）系统筛选了 2022 至 2026 年间的跨会议文献（其中约五分之一为反映前沿动态的预印本与非存档手稿），并提出了涵盖五项核心职责的参考架构：技能获取（Skill Acquisition）、记忆（Memory）、监控（Monitoring）、规划（Planning）与自我演化（Self-Evolution），工作流横跨在线执行与离线维护双阶段6。该综述同时梳理了两篇同期并发的运行时综述：Zeng 等人从基座模型外部运行步骤切入划分六项功能职责，而 Huang 等人则将 Harness 界定为治理技能调用的控制平面13。

在细分专题综述方面，2026 年 10 月的三篇代表作进一步厘清了记忆、递归自改进与控制周期的理论边界。论文 arXiv:2610.41688v1 建立了机器人策略的记忆分类谱系，将 RT-1、Diffusion Policy、ACT、OpenVLA、Octo 与 π0/π0.5 界定为“无持久记忆基线”，指出固定窗口上下文（Fixed-Window Temporal Context）受限于位置淘汰机制，易造成近因冗余帧挤占早期关键决策线索，并严格区分了回顾视界（Retrospective Horizon）、动作视界（Action Horizon）与预测视界（Predictive Horizon），强调智能体需要状态时效修正以防物体移动引发陈旧信念9。研究 preprints.org/manuscript/202610.2080 从具身递归自我改进（Embodied RSI）视角，主张将协调接口的 Harness、存储经验的 Memory 与决定更新产物的 Improver 解耦以便准确归因，同时警示对 KV-Cache 管理与压缩的评估必须结合物理动作截止期限、观测陈旧度与任务结果，而不能单纯以每秒 Token 数作为优化指标26。综述 arXiv:2610.21171v1 则明确区分了在线闭环执行（利用新观测更新物理状态与进度估计而不改写权重）、非参数记忆刷新与离线模型参数微调各自承担的闭环职责27。

在 GitHub 开源导航维度，四个主流 Awesome 仓库与两个专题笔记库构成了核心文献雷达4。其中 benchflow-ai/awesome-embodied-agents 在仓库简介中将“面向编码智能体的机器人 Harness（robot harnesses for coding agents）”单列为核心类别，与机器人模型、世界模型、基准、仿真器和数据集并列（需要说明的是，该仓库 README 全文在本次调研期间未能直接抓取，上述定性依据来自仓库公开介绍与检索片段）4。wadeKeith/Awesome-Embodied-AI 汇聚了 430 余项跨越 10 大赛道的资源，并专门设立指令安全与策略攻防（SafeVLA、AttackVLA、RoboSafe、VLA-Forget 等 2025–2026 年文献）版块7。zchoi/Awesome-Embodied-Robotics-and-Agent 与 yuxiang-gao/awesome-embodied-agent 分别聚焦 VLM/LLM 驱动的 VLA 模型迭代与人形机器人通用策略表征28。此外，ImChong/Robotics_Notebooks 与 will-rice/llm-self-improvement-papers 对 2026 年最新论文和开源仓进行了精细的源码级归档与交叉引用30。

核心演进范式：从端到端 VLA 到“外挂运行时（Embodied Harness）”

端到端 VLA 模型虽然能够直接从图像与语言映射出连续动作块，但当物体摆放发生空间置换、任务目标微调或操作出现滑脱时，单体策略往往陷入局部重复试探或丢失任务状态10。2026 年兴起的 Embodied Harness 范式确立了一条新的工程路径：将底层 VLA 降格为处理局部接触动态的“可重试原语（Primitive）”，而把非接触段的空间移动、语义重绑定、异常诊断与经验进化全部剥离至外部运行时软件层5。

在开源实现与基准验证方面，清华大学、跨步智能、无问芯穹等机构于 2026 年 7 月推出的 Harness VLA（arXiv:2607.08448v3，代码开源于 https://github.com/RLinf/RPent，记忆语料发布于 Hugging Face RLinf/RPent-memory）具有代表性5。该框架将冻结的 VLA（分别采用 RLinf 发布的 π0.5-SFT 检查点、RLDX-1 与 LingBot-VLA）暴露为短脉冲接触原语 vla_act，与固定词表的解析原语（move_to、move_pose、rotate_*、set_gripper、release 及移动导航原语）共同交给 Claude Code（CC）或 Codex 规划器以 JSON 形式调用，并在部署阶段严格禁止创造新原语5。作者对原语调用结构的统计揭示了该方法奏效的核心原因：在标准 LIBERO 上，vla_act 仅占全部原语调用次数的 15.8%，其余 84.2% 的非接触空间过渡均由确定性解析原语承担（RoboCasa365 上 vla_act 占比 35.3%，RoboTwin C2R 上为 47.4%）5。通过先在参考初始状态上搜索轨迹并沉淀出“任务专属记忆（将绝对坐标符号化为感知查询的 JSONL）”与“全局记忆（可复用规则与失败模式）”，Harness VLA 在抗扰动基准 LIBERO-Pro 上达到 82.4% 成功率（CC 规划器）与 72.1%（Codex 规划器），较 RATS 基线提升 38.6 个百分点（同骨干冻结策略直接运行仅 50.0%）；在 RoboCasa365 上达到 55.4%（较 RLDX-1 的 30.0% 提升 25.4 个百分点），在双臂 RoboTwin C2R 上达到 58.4%5。2026 年 11 月，无问芯穹与地瓜机器人进一步宣布将 RPent 纳入双方共建的具身开源基础设施矩阵（涵盖 RLark、RLinf、RPent 与 APXInf）38。

尽管零训练泛化增益显著，Harness VLA 这类在回合内频繁调用云端大模型 API 进行规划的模式随即暴露出严峻的延迟瓶颈。文献 arXiv:2609.29166v1 实测显示，Harness VLA 在 LIBERO-Pro Swap 与 Task 扰动上的单回合（Rollout）耗时分别达到 1,134.9 秒和 978.1 秒23；后续基于 RPent 的研究 AgenticRoboRL（arXiv:2610.28589v1）甚至需将单回合上限设为 100 轮规划或 7,200 秒22。为打破在线慢思考导致的耗时僵局，2026 年下半年迅速演化出两类高效率改进方向。

第一类方向是将在线多步规划下沉为“回合间演化的固定控制程序”。HarnessPAI（项目页 https://darwin-agent.github.io/HarnessPAI/，当前暂未见关联 arXiv 编号或公开源码仓）主张在单次回合内不调用高层 LLM 推理，而是运行由外部演化循环（定义 → 执行 → 诊断 → 校验与保留）生成的可执行程序，在内部显式组合视觉感知、几何推理、VLA/WAM 原语调用与成功检查，并借助 VLM 诊断与技能记忆在回合之间迭代修补程序逻辑15。根据其项目页披露的评测数据，HarnessPAI 将 π0.5 在 LIBERO-PRO（Swap + Task）上的总体成功率从 34.9% 推升至 96.5%（+61.6 个百分点），且基于 π0.5 演化的任务程序无需重新演化即可直接迁移至 DreamZero 后端（在 LIBERO-PRO Object 上将 Swap 从 0.6% 提升至 73.4%、Task 从 9.6% 提升至 84.4%）15。在 LIBERO-Goal Task 1 上，其串行执行速度较 Harness VLA 提升 23.1 倍（Swap）与 18.4 倍（Task），且回合内在线高层 LLM API 费用为零；但项目页亦明确加注限制说明——该加速比仅衡量部署串行执行开销，并未计入程序研发与演化阶段的生命周期成本15。

第二类方向是多时间尺度自演化运行时与本地小模型策略内化。2026 年 8 月发布的 Zetta (ζ)（arXiv:2608.16590，项目页 https://air-embodied-brain.github.io/zetta/，代码仓 air-embodied-brain/Zetta-Embodiment）在冻结底层动作策略与高层仲裁智能体（Orchestrator）的前提下，构建了“动作-批次-迭代”三层协调闭环：利用诊断智能体与演化智能体将失败簇抽象为机制级不变量，在线下迭代改写可执行的运行时评论家（Critics）、恢复策略（Recovery）与辅助工具（Tools），并结合硬件解耦的确定性路由调度层确保多卡仿真环境下批次对比无偏，经过隔离留出集验证后合并版本35。第三方开源追踪平台 OpenTrain 记录该仓库已收获 1,326 Stars（截至 2026 年 10 月底最后推送），但尚未提供官方发布标签（Tagged Releases）或 Docker 配置，且检索到的论文片段未披露具体分项基准百分数41。同类免权重更新演化框架还包括同步演化文本技能与上下文代码 Harness 的 SHAPER（arXiv:2608.11350v1/v2，验证于 VLABench 与 ESI-Bench）42、针对历史依赖型操作修订高阶 VLM 上下文规则的 SERA（arXiv:2610.29560v1，在 RoboMME 上将成功率从 44.38% 提高至 51.38%）14、集成六大功能模块的通用框架 EVA（OpenReview 匿名评审版本及代码 anonymous.4open.science/r/eva-0，在 VLABench 较基线提升 37.8% 且降低 10.9 倍 Token 开销并已部署于真实人形机器人）21，以及 2026 年 11 月 20 日最新发布的双智能体递归自改进框架 Embodied-Harness（arXiv:2611.27689v1）44。此外，AgenticRoboRL（arXiv:2610.28589v1）探索了另一种彻底摆脱庞大外部记忆与云端 API 的路径：利用 Qwen3.8-27B 配合 Harness VLA 记忆生成的教师轨迹对 Qwen3.5-9B 进行监督微调，再通过 2,304 回合结果奖励强化学习优化规划器；最终，这个 9B 本地规划器在完全不访问外部记忆文件的条件下，在 LIBERO-PRO 上的成功率从 18.1% 跃升至 71.0%，几乎追平依赖外部记忆的 Codex (GPT-5.5)（72.1%），并在 CaP-X 框架下将成功率从 2.7% 提高至 28.5%22。

长程记忆与执行校验机制深度拆解（含同名 HELM / HeLM 辨析）

检索 2026 年具身记忆文献时极易遭遇一处名称碰撞：两篇分别于 2026 年 4 月和 11 月发表的独立研究均以“HELM / HeLM”命名，但二者在记忆载体、问题焦点与系统层级上截然不同12。

第一篇是 Zeng 等人于 2026 年 4 月发布的 HELM（Harness-Enhanced Long-horizon Memory，arXiv:2604.18791）16。作者通过系统性剖析揭示了单步 VLA 在长程操作中反复出现的三大执行循环缺口：固定窗口遗忘已完成子目标（例如在 t=47 步无法记起 t=12 步已将杯子放入橱柜而重复抓取）导致的记忆缺口（FM）、缺乏前置可行性判断导致错误抓取或越界运动静默执行的校验缺口（FV），以及某一步失败后策略在受损状态下继续推进引发级联失败的恢复缺口（FR）10。为此，HELM 在冻结 VLA 外部构建了情景记忆模块（EMM，基于 CLIP ViT-B/32 嵌入索引关键帧与深度估计状态增量，在子目标完成、检测到失败或每 20 步写入，容量上限 50 条，按余弦相似度检索 Top-3 序列化为文本注入 VLA 语言输入）、记忆条件化的预执行失败预测器状态校验器（SV），以及触发状态回滚或前向恢复的控制模块（HC），并伴随发布故障注入评测协议 LIBERO-Recovery10。

HELM 的受控消融实验提供了极具参考价值的训练预算分配洞察（基于 OpenVLA）：将上下文窗口从 H=8 暴增至 H=32 仅换取 +5.4 个百分点的任务成功率（TSR 为 63.8%）；将 5 万步环境轨迹（约 2 小时采集）直接用于 LoRA 微调 OpenVLA 主干仅达 69.3% TSR；而把相同的 5 万步预算用来训练轻量级的记忆条件化状态校验器 SV，配合 EMM 与 HC，完整版 HELM 达到 81.5% TSR，高出同预算 LoRA 微调 12.2 个百分点，且单步推理仅增加约 12 ms（在单张 A100 上约为骨干耗时的 15%）11。对比测试还显示，单靠手工规则校验器仅能带来 +6.8 pp 提升，5 模型集成不确定性虽有 +9.5 pp 却需付出 5 倍推理成本，而单模型 SV 实现了 +8.4 pp 的均衡收益；更重要的是记忆与校验之间的强耦合——一旦移除记忆上下文，SV 的贡献会下降 6.1 个百分点（其中移除 Top-1 检索记忆使 SV 的 AUROC 从 0.847 跌至 0.791）11。最终 HELM 分别将 FM、FV 与 FR 类故障削减了 76%、61% 与 82%；考虑到真实物理机器人在失败后无法像仿真器那样一键状态回滚，作者专门提供了无需物理重置的前向恢复变体 HELM-Fwd（达成 76.3% TSR 与 38.7% RSR），并验证了框架在 Octo 骨干上的可迁移性（+21.6 pp）10。

第二篇则是韩国首尔国立大学（SNU）团队于 2026 年 11 月提出的 HeLM（Hierarchical Explicit Language Memory，arXiv:2611.02660，开源仓库 https://github.com/kimspacehuni/HeLM，项目页 https://kimspacehuni.github.io/HeLM/）12。SNU 团队指出，大多数 VLA 隐含马尔可夫假设，仅依赖当前观测无法区分处于不同历史阶段但画面相同的场景12。受人类“内心独白（Inner Monologue）”启发，HeLM 引入微调后的高层 VLM 策略（HLP）充当显式语言记忆管理器，并在两种模式间切换：每帧执行的检测模式（Detect Mode）负责比对 TaskSpec 中定义的任务关键事件；仅当检测到有效事件或全局指令发生切换时，才触发更新模式（Update Mode）改写结构化语言记忆（拆分为回合内工作记忆与跨回合情景记忆）并向底层 VLA 策略（如 π0）下发新的原子指令12。

这种“事件触发的自然语言压缩”有效克服了视觉历史帧随任务拉长而不断膨胀的痛点。在 10 项真实世界非马尔可夫操作任务（56 个变体）评测中，HeLM 的回合内（Intra-episode）平均子任务成功率达 85.7%，领先共享同一 HLP 骨干的视觉关键帧基线 Keyframe-HLP（72.9%）12.8 个百分点，也大幅超越将 MemoryVLA 认知记忆库适配至 π0 的潜在视觉基线 PCMB-π0（39.5%）；而在跨回合（Inter-episode）连续任务评测中，Keyframe-HLP 因视觉帧跨指令堆积崩溃至 16.6%，HeLM 依然维持了 89.2% 的成功率，同时在长程阶段比 Keyframe-HLP 最高节省 4.5 倍内存并实现 2.5 倍推理加速12。HeLM 仓库的 helm_datasets/ 包开源了从 LeRobot 演示视频抽取并标注约 13 万帧事件数据集的完整流程；此外，HeLM 官方 README 明确注明，Zeng 等人的 Harness-Enhanced HELM 属于另一项独立研究，HeLM 论文并未与之进行同台对比评测46。

除双 HELM 外，2026 年多篇研究也从不同侧面完善了记忆与校验版图。Goal2Skill（arXiv:2604.1394224）构建了“情景历史 + 工作记忆 + 错误登记表”三元结构，通过自演化校验器在子任务层面决定继续、推进或仅重写剩余规划步骤，并在向底层动作策略传输图像前用分割与跟踪模块掩膜屏蔽无关干扰物（同时保留原始图像供高层模块审查）24。不过据 alphaXiv 与 OpenResearch 的独立论文摘要评注，Goal2Skill 的定量主结果目前仅依托 RMBench 选定的 5 项任务（总体平均 32.4% vs MemER 10.2%，其中 4 项领先），反射消融仅覆盖 2 项任务（28.0% vs 17.5%），且校验器更新仅给出了单个摇摆计数定性案例，尚不足以证明跨任务普适鲁棒性24。SOMA（arXiv:2603.24060）聚焦面向 VLA 抗扰动的上下文自适应编排与记忆增强51；而 WeaveLA（事件触发潜记忆）、ECHO（分层经验检索）、ReMem-VLA（帧与动作块级循环查询）与 Cortex（任务上下文记忆加技能约束）也分别在跨子任务信息传递和部署约束校验方向推进了长程控制边界14。

物理 AI 运行时、ROS/MCP 中间件与多机系统工程生态

如果说前述算法论文着眼于“如何提升长程与抗扰动成功率”，那么 GitHub 上蓬勃发展的具身软件基础设施则重在解决“如何把大模型推理安全、标准、可审计地接入 ROS 1/ROS 2、物理仿真器与多异构机器人本体”18。在这一工程赛道中，必须首先厘清两个同名但架构路线不同的 ROSClaw 开源项目20。

第一个分支是 PlaiPin / OpenClaw 路线的 ROSClaw（arXiv:2603.26997，代码仓库 https://github.com/PlaiPin/rosclaw，615 Stars / 66 Forks，当前仓库公告正进行向多仓库拆分迁移的重构）20。该框架由 Irvin Steve Cardenas 等人于 2026 年 3 月底推出，主打通过 OpenClaw 插件让用户借助 Telegram、WhatsApp、Discord 或 Slack 等即时通讯工具控制 ROS 2 机器人，并内置独立于 AI 的 /estop 急停通道20。其核心学术贡献在于将“认知层与执行层边界”形式化为四元组执行层契约 C = ⟨A, O, V, L⟩：动态内省 ROS 2 计算图以暴露标准化能力清单 A（Affordance Manifest）、多传感器观测归一化器 O、依据安全策略 P 在指令下发前做出 ALLOW 或 BLOCK 裁决并附带解释理由的预执行校验器 V，以及全量结构化审计日志 L19。系统抽象了 8 个标准 ROS 2 工具并支持三种传输模式（本地 DDS 延迟低于 1 ms、rosbridge WebSocket 为 5–10 ms、WebRTC P2P 为 20–100 ms）；实测表明大模型单轮推理耗时 1.3–2.3 秒（P95 不超过 3.8 秒），远高于底层通信开销19。通过与 NASA JPL ROSA 进行严格对等协议（Parity Protocol）评测，该研究发现影响物理任务完成率与违规尝试率的不只是提示词工程，执行层契约设计与数字安全上限在上下文中的显式呈现同样起着关键作用19。

第二个分支则是由 同济大学与 SRIAS 团队主导的 ROSClaw 物理 AI 运行时（arXiv:2604.04664，官网 https://www.rosclaw.io/，代码仓库 https://github.com/ros-claw/rosclaw，240 Stars / 34 Forks，组织名下共计 42 个仓库）18。其设计理念定位为连接任意智能体与任意物理本体的双向运行时（Act → Verify → Remember → Evolve），贯彻“请求不等于执行，下发不等于完成，完成必须有证据”的工程原则——所有智能体意图必须经过能力绑定、权限仲裁与驱动调度，并返回附带物理执行证据的 ExecutionReceipt18。在物理安全层面，论文 2604.04664 引入了基于 Isaac Lab 与 e-URDF 的无头数字孪生沙箱，在下发真机资源池前先完成碰撞检测与关节力矩校验，并在人形机器人、固定机械臂与移动操作平台的异构协同中实现约三分钟完成多云台协同编舞的快速部署57。ros-claw 组织目前正高速孵化全栈组件，涵盖基于 USD 的自动化场景生成工具 simscene（43 Stars）、行人交互模拟 simpeople（14 Stars）、零 ROS 依赖的时空因果图记忆库 rosclaw-memory（基于 PowerMem + SeekDB，7 Stars）、宇树机器人 MuJoCo MCP 服务 unitree-mujoco-mcp（6 Stars）、物理常识防火墙 rosclaw-wiki（5 Stars），以及评测物理反馈自演化与跨本体迁移的基准 PhysicalEvoBench 与 PhysicalEvoBench-X55。同时该仓库文档也保持了审慎的工程透明度：虽然本地 Codex CLI 黑盒测试已成功发现全部 22 个 MCP 工具并验证 rosclawd 能够拦截未授权真机动作，但独立 H5 验收与受控 Agent A/B 对比验收仍处于待完成（Pending）状态18。

在机构级开源多机协同生态方面，北京智源人工智能研究院（BAAI） 持续推动 RoboBrain 与 RoboOS 协同演进58。在认知基座端，研究团队从 CVPR 2025 的 RoboBrain 1.0（arXiv:2502.21257），经结合空间指代 RoboRefer（arXiv:2506.04308）与强化微调 Reason-RFT（arXiv:2503.20752）的 RoboBrain 2.0（arXiv:2507.02029，提供 3B/7B/32B 权重及 FlagScale W8A16 压缩加速），于 2026 年 1 月升级为具备原生 3D 空间追踪（RoboTracer）与时间思维能力的 RoboBrain 2.5（arXiv:2601.14352）58。在操作系统端，RoboOS 1.0（arXiv:2505.03673）通过 Redis 主从架构协调单臂、双臂、人形与轮式异构机器人在餐厅、家庭和超市等场景协作；随后的 RoboOS 2.0 升级为“SaaS + MCP”无服务器部署架构（注：此处 MCP 指 Multi-Entity Collaborative Platform 即多实体协同平台，有别于前述 Anthropic 的 Model Context Protocol），而 RoboOS-NeXT（2025 年 10 月发布）则进一步构建面向终身学习与可扩展跨本体协作的统一记忆框架59。

此外，传统工程工具链的生态格局在 2026 年底亦出现了明显洗牌。NASA JPL 开源的 ROSA（https://github.com/nasa-jpl/rosa，1.7k Stars / 189 Forks，Apache-2.0，支持 pip3 install jpl-rosa）依托 LangChain 长期作为 ROS 1/ROS 2 自然语言巡检、排障与操作的事实参考标杆（Reddit r/ROS 社区讨论帖中有自称参与人类评估的开发者声称其在非平凡多跳诊断查询中比人类专家快 10–50 倍、单次调用成本约 0.25 美元，但该数值属非独立审计的社区证言）52。与之形成对比的是曾高调对标“机器人领域 Android”的跨本体硬件抽象层 OpenMind OM1（https://github.com/OpenMind/OM1，支持 ROS2、CycloneDDS、Zenoh、Gazebo、Prometheus 监控及宇树 Go2/G1 等全自主套装）——该仓库已于 2026 年 11 月正式宣布归档（Archived），停止 GitHub 主动维护并将后续动态迁回 openmind.com68。与此同时，Trendshift 2026 年 10 月下旬至 11 月中旬榜单反映出一批轻量级 CLI、MCP 与“Vibe Roboting”编码桥接工具正在快速吸纳开发者关注，包括 arpitg1304/robotics-agent-skills（401 Stars）、fujitatomoya/ros2ai（335 Stars）、strands-labs/robots（215 Stars）、PhysicalRSI/PhysicalRSI（145 Stars）以及直接接入 Claude Code 与 Codex 的 terminalworld/OpenRUA（59 Stars）17。

头部实验室基座模型与工业双/三系统架构对比

在外部 Harness 之外，头部商业实验室与开放基座生态在 2025 至 2026 年间同样把注意力集中于快慢异步分层控制与世界模型合成数据飞轮2，形成了四股主导技术力量。

Physical Intelligence（openpi 生态） 确立了流匹配（Flow-Matching）动作模型与双系统层次化的开源标准29。该团队从基于逾 10,000 小时跨 7 种构型数据预训练的 π0（arXiv:2410.24164）与高效动作分词 FAST（arXiv:2501）起步，于 ICML 2025 推出 Hi Robot（arXiv:2502.19417）——高层策略与底层 π0 均从同类 PaliGemma-3B 骨干初始化，由高层模型将开放长指令及人类现场插话实时转译为底层已掌握的短语言子命令（截至检索记录，Hi Robot 项目页未单独放出专属实现与数据下载，但 π0 与 π0.5 已通过 https://github.com/Physical-Intelligence/openpi 完整开源）29。此后团队又推出使用约 400 小时百户真实家庭数据训练的开放世界泛化模型 π0.5（arXiv:2504.16054）与具备经验学习能力的 π*0.6（arXiv:2511），使 openpi 成为 Harness VLA、HeLM 及 AgenticRoboRL 等众多外挂框架评测底层的默认参照系5。

NVIDIA Isaac GR00T 与 Cosmos 栈 则走出了全栈开源工业基座与合成数据飞轮的路线77。在 https://github.com/NVIDIA/Isaac-GR00T 中，模型历经 N1、N1.5、N1.6 迭代至采用商业友好型 NVIDIA Open Model License 授权的 GR00T N1.7-3B77。自 N1.6 起，NVIDIA 用支持原生纵横比无填充编码的 Cosmos-Reason2-2B（及变体）取代早期的 Eagle VLM 骨干，移除旧版 4 层后置适配器并改为解冻 VLM 顶层 4 层联合训练，同时将扩散 Transformer（DiT）动作头从 16 层翻倍至 32 层、输出状态相对动作块（State-Relative Action Chunks），并预置 LIBERO_PANDA、UNITREE_G1 与 BEHAVIOR_R1_PRO 等微调配置（官方教程文档同时披露，受图像增强与随机过程非确定性影响，同配置跨轮次训练仍存在 5%–6% 的性能波动）79。配合利用 Cosmos-Predict2 视频世界模型生成视频并经逆动力学模型（IDM）抽取动作转为 LeRobot 格式的 https://github.com/nvidia/gr00t-dreams（633 Stars / 61 Forks），以及提供 GR00T-N1.7 与 π0.5 联合 PPO 后训练管线的 https://github.com/NVIDIA/cosmos-framework，NVIDIA 打通了“视频世界模型生成数据 → DiT 动作头微调 → 在线强化学习对齐”的闭环工程工具链72。

Google DeepMind Gemini Robotics 系列 与 Figure AI Helix 系列 则代表了闭源受控生态下的全身灵巧操作前沿1。Google DeepMind 在发布 Gemini Robotics（arXiv:2503.20020，千小时级动作数据，新任务仅需不超过 100 条演示即可实现 70% 以上成功率）与具备跨本体运动迁移（覆盖 ALOHA、双臂 Franka 与 Apptronik Apollo）及具身思维链的 Gemini Robotics 1.5 / ER 1.5（arXiv:2510.03342）及 ER 1.6 之后，推出了 Gemini Robotics 2、ER 2 与 On-Device 21。根据 DeepMind 官方博客介绍，ER 2（已上线 Google AI Studio 及企业代理平台私密预览）负责多步长程推理与多机协作编排，而面向早期合作方开放的 GR 2 首次实现 Apptronik Apollo 2 从双足到 22 自由度五指灵巧手（SharpaWave）的全身统一控制，完成系结与封自封袋等高难度操作；团队并同步发表了围绕 ISO 10218:2025 人机协作标准的安全评估报告1。Figure AI 在 2025 年 2 月首代 Helix（约 7B 参数 System 2 以 7–9 Hz 推理 + 80M 参数 System 1 以 200 Hz 控制 35 自由度上肢，基于约 500 小时遥操作数据训练并部署于低于 60W 的机载 Jetson Orin）的基础上，于 2026 年 2 月发布了 Helix 022。Figure 官方博客显示，Helix 02 新增了在逾 20 万个并行仿真环境中、由超 1,000 小时重定向人类动作练就的 10M 参数 System 0（1 kHz 全身平衡与运动先验），将 200 Hz 的 System 1 扩展至头部相机、掌心相机与灵敏度达 3 克的指尖触觉传感器，实现了在真实厨房场景中不中断执行 61 个连续动作（持续数分钟，含用髋部顶关抽屉、药盒单粒取药、注射器精准推注 5 ml 与杂物分拣）的全身自主控制2。第三方媒体评论称 Figure AI 为此删除了 109,504 行传统 C++ 控制代码，但该具体删除行数未见于 Figure 官方新闻稿2。

结构性瓶颈、安全治理与技术路线权衡

综合上述论文成果与系统工程实践，当前具身智能体的架构设计正集中面对三组核心权衡与安全边界约束。

其一，实时推理延迟与外挂经验沉淀的双向闭环。 端到端分层神经栈（如 Helix 02）能够凭借 200 Hz 至 1 kHz 的控制频率实现全身动力学协同，但极度依赖昂贵的真实触觉与海量仿真对齐2；反观调用前沿大模型的纯在线外挂 Harness（如 Harness VLA），虽然零微调即可在扰动基准上提升近 39 个百分点，却需要近 20 分钟完成单回合运行5。2026 年下半年的最新探索正在架设一条折中桥梁——将非参数化 Harness 转化为“高可靠性示范轨迹的自动生产工厂”：HarnessPAI 先以跨回合演化的控制程序跑通高扰动场景，再借助严格的环境成功检查门控筛选成功轨迹，反向微调底层 π0.5 策略，使其在 LIBERO-PRO 上的单模型成功率从 34.9% 跃升至 73.7%（+38.8 个百分点）15；AgenticRoboRL 用结果驱动强化学习把外部记忆搜索内化进 9B 本地模型22；ROSClaw 亦把受验证的物理交互积累至本地资源池用于持续优化策略57。从当前演进趋势来看，具身智能体正逐步脱离“纯端到端模型”与“纯大模型外挂”的二元对立，向“本地高频运动控制 + 轻量级记忆与状态校验（如 HELM 仅约 12 ms/step 开销） + 异步离线 Harness 演化与数据蒸馏”的混合范式收敛2。

其二，机器人数据经济学限制与世界模型的真实乘数边界。 据 Cervo-Tech 2026 年统计汇总，相较于 Llama 3 超过 15 万亿 Token 的互联网文本预训练规模，最大开源真实机器人数据集 Open X-Embodiment 仅约 100 万条轨迹（约 2,000 小时操作数据），AgiBot World Beta 约 2,976.4 小时，而仅 350 小时的 DROID 数据集便耗费了跨三大洲 50 名采集员整整 12 个月的日历时间75。高昂的人力与时间成本（如行业报道特斯拉曾为动捕数据员开出最高 48 美元/小时薪资，Interact Analysis 报告中国已有 64 座数据采集中心运营、20 座在建）推动了世界模型合成管线的普及，例如引用数据显示 GR00T N1.5 用 36 小时合成数据替代了约 3 个月人工采集75。但必须正视的物理局限在于：所有已公开管线的金字塔顶端仍需真实遥操作轨迹作为锚点（例如 GR00T N1 仍依赖 88 小时真机数据作种子），且如 preprints.org/manuscript/202610.2080 所指出的，视频-动作联合生成模型本身并不能保证预测的未来画面必然严格符合真实物理动作后果26。

其三，自演化智能体的物理安全边界与可治理契约。 当外挂 Harness 能够在部署期间自行编写运行时评论家、新工具和恢复剧本时，传统的静态权限模型正面临失效风险。实证方面，PlaiPin ROSClaw 论文通过跨模型对等实验证明，即便底层硬件、能力清单和速度阈值完全一致，不同大语言模型主动发起物理违规请求的“尝试率”仍存在较大离散度19；而 DeepMind 的《Gemini Robotics 2: Safety Evaluations》报告则量化表明，向模型注入详尽物理可行性上下文（开发者指令）对其安全判定至关重要——模型在无详尽感知（DI0）下的分类准确率仅为 62.0%，随上下文感知度提升至最高层级（DI3）后攀升至 95.8%86。理论治理方面，研究 arXiv:2607.05463v2 指出，一旦自演化智能体在运行后习得新技能，“部署运行的智能体已不再是上线前通过签名认证的原始制品”，静态凭据与一次性溯源验证无法约束演化后的物理越界92。该视角文章建议建立“可治理个体抽象（Governable-Individual Abstraction）”：强制要求智能体新增的每项技能声明其“影响类别契约（Effect-Class Contract）”并在准入时对照承诺边界核验，同时引入运行时“动态影响追踪器（Dynamic Effect Tracer）”拦截实际触碰越权物理对象的动作——作者报告该机制在测试集上将误放行（false-allows）降至零，但也坦陈该保障成立的前提是动作空间存在可靠的影响校验器，且应对自适应供应商与云端推理非确定性的证明仍属开放课题92。
